# Acceptance Criteria Builder

Primary journey: **Design**

Make requirements testable.

## Artifact

When project files are writable, create or update `docs/forgemind/acceptance/<feature-or-story>.md`.

## Output

- Acceptance criteria
- Positive test cases
- Negative/edge cases
- App-level smoke test
- Non-functional checks
- Definition of done
- Verification commands or manual checks

Criteria must be observable and testable. Avoid vague words like "fast", "nice", or "better" unless measurable.
