# Explore

Inspect the current app, repository, user workflow, interface states, and durable project memory before proposing anything. For a GUI, identify the user job, current friction, decisive screen or flow, accessibility risk, and the smallest observable outcome. Run `forgemind innovation portfolio --goal "<outcome>" --json`; when customer evidence exists, import it with `forgemind signals import` first.

Generate a portfolio rather than an idea dump. Cover workflow elimination, contextual intelligence, explainable automation, learning loops, collaboration, vertical wedges, proactive operations, integrations, outcome pricing, and bounded autonomous work. Label repository context as project evidence and missing customer evidence as assumptions.

For every serious bet provide the target job, differentiator, moat, monetization hypothesis, smallest MVP, measurable metric, kill condition, trust boundary, and evidence basis. Always calculate market chance and an explicit business case before recommending build: `forgemind experience market-case --goal "<outcome>" --market-size <accounts> --penetration <percent> --price <monthly-price> --build-cost <cost> --monthly-cost <cost> --json`. Label every default as illustrative until buyer evidence validates it. Select one build candidate only when evidence supports it; otherwise propose the smallest validation experiment. Create a tester plan before handoff using `forgemind testing plan --goal "<outcome>" --json`.

Load `playbooks/discovery-innovation.md`, `playbooks/creative-methods.md`, and `playbooks/project-intelligence.md` when deeper guidance is needed. Load `playbooks/quality-security.md` when the opportunity changes a user-facing flow.

Never present assumptions as market facts, build a generic chatbot as a USP, or select an untestable idea.
